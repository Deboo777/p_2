# Инструмент визуализации графа зависимостей для менеджера пакетов Alpine (apk)

Программное обеспечение представляет собой CLI-приложение на языке Python, предназначенное для автоматического сбора, анализа и визуализации транзитивных зависимостей пакетов Alpine Linux (`apk`). Проект выполнен в рамках учебного задания (Вариант №20) без использования сторонних системных пакетных менеджеров или специализированных библиотек для работы с зависимостями.

---

## 1. Функциональные возможности и требования

Архитектура инструмента разбита на логические модули, соответствующие пяти этапам проектирования:
1. **Конфигурация:** Инициализация параметров через YAML-файл, обрабатываемый специализированным отказоустойчивым парсером.
2. **Сбор данных:** Автоматическая загрузка индекса репозитория (`APKINDEX.tar.gz`), его распаковка в оперативной памяти и извлечение прямых зависимостей с очисткой от версионных суффиксов.
3. **Анализ графа (DFS):** Рекурсивное построение транзитивного графа зависимостей методом обхода в глубину с детекцией циклических зависимостей, ограничением максимальной глубины и фильтрацией по подстроке.
4. **Тестирование:** Поддержка изолированной "песочницы" (Test Mode) для загрузки абстрактных графов, заданных латинскими символами.
5. **Топологическая сортировка:** Расчет детерминированного порядка загрузки и установки пакетов в операционную систему.
6. **Визуализация:** Генерация иерархического ASCII-дерева в консоли и формирование программного кода для построения классических компонентных диаграмм в системе PlantUML.

---

## 2. Спецификация конфигурационного файла (`config.yaml`)

Управление утилитой осуществляется через файл настроек `config.yaml`, расположенный в корневой директории приложения.

### Шаблон конфигурации:
```yaml
package_name: "curl"
repository_url: "https://alpinelinux.org"
test_mode: false
ascii_tree_output: true
max_depth: 5
filter_substring: "musl"
```

### Описание параметров:
* `package_name` (string): Идентификатор исследуемого пакета (например, `"curl"` или `"A"` для тестового режима).
* `repository_url` (string): Прямой URL-адрес файла `APKINDEX.tar.gz` или относительный путь к локальному файлу описания тестового графа.
* `test_mode` (boolean): Флаг переключения между боевым репозиторием Alpine (`false`) и локальной отладкой графов (`true`).
* `ascii_tree_output` (boolean): Разрешение на вывод древовидной структуры зависимостей в текстовом виде прямо в терминал.
* `max_depth` (integer): Максимально допустимая глубина рекурсивного спуска алгоритма DFS.
* `filter_substring` (string): Подстрока-фильтр. Любой пакет, содержащий данную строку в имени, исключается из анализа.

## 3. Архитектура программных модулей

Инструмент реализован в едином исполняемом модуле `CLI.py`. Логическая структура функций выглядит следующим образом:

* `parse_yaml_config(file_path)` — Ручной парсер параметров. Читает файл построчно, отсекает комментарии (`#`), валидирует типы данных (`int`, `bool`, `string`) и формирует словарь конфигурации.
* `clean_dependency_name(dep_string)` — Модуль нормализации данных. Использует регулярные выражения для очистки строк зависимостей от условий версионирования (удаляет операторы `=`, `>=`, `<`, `~` и последующие символы).
* `fetch_apk_index(repo_url)` — Сетевой клиент. Отправляет HTTP-запрос с подменой заголовка `User-Agent`, считывает бинарный поток архива и извлекает текстовый индекс `APKINDEX` без создания временных файлов на диске.
* `parse_apk_index(content)` — Семантический анализатор структуры базы данных Alpine. Разделяет текст на блоки пакетов и формирует ассоциативный массив связей `{Пакет: [Прямые зависимости]}`.
* `load_test_repository(file_path)` — Загрузчик абстрактных графов. Парсит упрощенный синтаксис вида `A: B C` для проведения тестов на цикличность.
* `build_dependency_graph(...)` — Ядро системы. Рекурсивный алгоритм DFS. Контролирует текущую глубину, отслеживает циклы с помощью стека пути `path` и формирует итоговый граф.
* `print_ascii_tree(...)` — Визуализатор терминала. Выводит древовидную структуру зависимостей с отступами и маркерами `└── `.
* `generate_plantuml(graph)` — Экспорт данных. Автоматически объявляет сущности как `component` и связывает их стрелками `-->`, генерируя валидный код для компонентных диаграмм PlantUML.

---

### 3.1. `parse_yaml_config(file_path)`
* **Назначение:** Инициализация и конфигурирование окружения без использования тяжелых внешних парсеров (программная изоляция).
* **Входные данные:** `file_path` (string) — относительный или абсолютный путь к конфигурационному файлу на диске.
* **Выходные данные:** `config` (dict) — ассоциативный массив, где ключами являются параметры конфигурации, а значениями — приведенные типы данных Python.
* **Алгоритм и логика:**
  1. Метод открывает текстовый файл в кодировке `utf-8` и выполняет построчное чтение.
  2. Из каждой строки удаляются концевые пробельные символы (`.strip()`). Строки, начинающиеся со знака `#` или являющиеся пустыми, игнорируются (пропуск комментариев).
  3. Строка разделяется строго по первому вхождению символа `:` на пару `ключ: значение`.
  4. Значение очищается от возможных обрамляющих кавычек (`"`, `'`).
  5. Выполняется динамическое приведение типов: если строка состоит из цифр, она конвертируется в `int`; если строка эквивалентна `true`/`false` (без учета регистра), она приводится к логическому типу `bool`. В остальных случаях сохраняется тип `str`.
  6. При возникновении исключений (`FileNotFoundError`, `PermissionError`) дефекты перехватываются, приложение выводит информативное сообщение об ошибке и возвращает пустой словарь.

---

### 3.2. `clean_dependency_name(dep_string)`
* **Назначение:** Санитизация и нормализация строк зависимостей до каноничных имен пакетов.
* **Входные данные:** `dep_string` (string) — сырая строка зависимости из базы данных Alpine (например, `"musl>=1.2.2_r0"` или `"so:libssl.so.1.1"`).
* **Выходные данные:** `clean_name` (string) — очищенное имя пакета (например, `"musl"` или `"so:libssl.so.1.1"`).
* **Алгоритм и логика:**
  Использует механизм компилируемых регулярных выражений (`re`). Шаблон `^([^<=>~!]+)` захватывает все символы с начала строки до тех пор, пока не встретит один из операторов версионирования (`=`, `<`, `>`, `~`, `!`). Метод извлекает совпадение первой группы и удаляет пограничные пробелы. Если операторы версий отсутствуют, строка возвращается в исходном виде.

---

### 3.3. `fetch_apk_index(repo_url)`
* **Назначение:** Сетевой транспорт для получения бинарного архива метаданных.
* **Входные данные:** `repo_url` (string) — URL-адрес целевого репозитория Alpine Linux.
* **Выходные данные:** `packages_db` (dict) — плоская база данных всех пакетов репозитория, полученная из функции `parse_apk_index`.
* **Алгоритм и логика:**
  1. Строка URL очищается от случайных пробелов и кавычек.
  2. Формируется защищенный HTTP-запрос через `urllib.request.Request`. В заголовок принудительно внедряется валидный `User-Agent: Mozilla/5.0...`, что предотвращает блокировку со стороны систем защиты CDN Alpine (ошибка 403 Forbidden).
  3. Сетевой поток считывается в оперативную память как массив байт (`compressed_data`).
  4. С помощью встроенного модуля `tarfile.open` и обертки `BytesIO` байты интерпретируются как архив `tar.gz` непосредственно в памяти. Диск для создания временных файлов не используется, что повышает скорость работы и исключает проблемы с правами доступа.
  5. Метод находит файл `APKINDEX`, извлекает его содержимое, декодирует из `bytes` в строку `utf-8` и передает в парсер. При повреждении архива генерируется исключение `tarfile.ReadError`, которое безопасно обрабатывается.

---

### 3.4. `parse_apk_index(content)`
* **Назначение:** Синтаксический разбор внутренней структуры текстовой базы данных Alpine Linux.
* **Входные данные:** `content` (string) — сырой распакованный текст файла `APKINDEX`.
* **Выходные данные:** `packages_db` (dict) — отображение вида `{ "имя_пакета": ["зависимость_1", "зависимость_2"] }`.
* **Алгоритм и логика:**
  1. Текст разбивается на блоки по двойному переносу строки (`\n\n`), так как каждый пакет в формате Alpine отделен пустой строкой.
  2. Программа итерируется по каждому блоку, разбирая его построчно.
  3. Если строка начинается с префикса `P:`, извлекается имя текущего пакета.
  4. Если строка начинается с префикса `D:`, извлекается список его зависимостей. Строка разделяется по пробелам на отдельные элементы, каждый из которых пропускается через фильтр `clean_dependency_name`.
  5. По завершении блока в результирующий словарь добавляется пара `{Имя: [Список очищенных зависимостей]}`. Пакеты без зависимостей инициализируются с пустым списком `[]`.

---

### 3.5. `load_test_repository(file_path)`
* **Назначение:** Локальный провайдер данных для имитации репозитория в режиме изолированного тестирования (`test_mode: true`).
* **Входные данные:** `file_path` (string) — путь к локальному текстовому файлу графа на диске.
* **Выходные данные:** `packages_db` (dict) — заполненный словарь графа, аналогичный выводу `parse_apk_index`.
* **Алгоритм и логика:**
  Построчно считывает указанный файл. Строки-комментарии отбрасываются. Каждая валидная строка делится по символу `:` на имя абстрактного пакета (большая латинская буква) и список его зависимостей, разделенных пробелом. Строка `A: B C` преобразуется в структуру `{"A": ["B", "C"]}`.

---

### 3.6. `build_dependency_graph(package, db, max_depth, filter_sub, current_depth, graph, path, order, visited_nodes)`
* **Назначение:** Вычислительное ядро приложения. Рекурсивное построение направленного транзитивного графа и его топологическая сортировка.
* **Входные данные:** 
  * `package` (str) — текущий исследуемый пакет.
  * `db` (dict) — плоская база данных пакетов.
  * `max_depth` (int) — лимит глубины рекурсии.
  * `filter_sub` (str) — подстрока для исключения элементов.
  * `current_depth` (int) — маркер текущего уровня вложенности.
  * `graph`, `path`, `order`, `visited_nodes` — внутренние структуры состояния (словари, списки и множества для сохранения истории обхода).
* **Выходные данные:** Кортеж `(graph, order)`, где `graph` — построенный транзитивный граф связей, а `order` — линейный массив топологической сортировки порядка установки.
* **Алгоритм и логика (DFS с защитой от циклов):**
  1. **Фильтрация:** Если имя `package` содержит `filter_sub`, выполнение ветки немедленно прекращается.
  2. **Ограничение глубины:** Если `current_depth` превысил `max_depth`, рекурсивный спуск останавливается.
  3. **Защита от циклов:** Перед переходом к зависимостям имя текущего пакета проверяется на наличие в стеке `path`. Если пакет уже присутствует в текущем пути обхода (например, `A -> B -> C -> A`), программа фиксирует циклическую связь, выводит предупреждение `[INFO] Обнаружен цикл...` в консоль и осуществляет безопасный выход из ветки рекурсии (`return`), предотвращая переполнение стека (`RecursionError`).
  4. **Спуск:** Текущий пакет добавляется в стек пути `path`. Из базы данных `db` извлекаются его прямые зависимости. Те из них, которые не содержат отфильтрованную подстроку, записываются в итоговую структуру `graph[package]`. Для каждой отфильтрованной зависимости функция вызывается рекурсивно с увеличением `current_depth + 1`.
  5. **Топологическая сортировка:** После того как рекурсивные вызовы для всех зависимостей текущего пакета завершились (достигнуто «дно» графа), пакет извлекается из стека пути `path.pop()`. Если данный пакет еще не был обработан ранее, он заносится в множество `visited_nodes` и добавляется в конец списка `order`. Благодаря этому самые глубокие и независимые библиотеки всегда оказываются в начале списка `order`.

---

### 3.7. `print_ascii_tree(package, graph, depth, visited)`
* **Назначение:** Визуализация древовидной структуры в интерфейсе командной строки (CLI).
* **Входные данные:** `package` (str) — корень поддерева; `graph` (dict) — построенный граф; `depth` (int) — текущий уровень отступа; `visited` (set) — локальная копия посещенных узлов для предотвращения зацикливания при печати.
* **Алгоритм и логика:**
  На основе текущего параметра `depth` вычисляется количество пробелов для отступа (шаг — 4 пробела). Для дочерних элементов выводится маркер `└── `. Если узел уже встречался в данной ветке печати, рядом пишется маркер `(повтор/цикл)`, и функция возвращает управление. Метод рекурсивно обходит структуру, формируя наглядное дерево зависимостей.

---

### 3.8. `generate_plantuml(graph)`
* **Назначение:** Трансляция внутренней структуры данных Python в декларативный код графического языка разметки PlantUML.
* **Входные данные:** `graph` (dict) — транзитивный граф зависимостей.
* **Выходные данные:** `puml_code` (string) — валидный блок кода диаграммы.
* **Алгоритм и логика:**
  1. Из ключей словаря графа и списков зависимостей собирается общее множество (`set`) всех уникальных названий пакетов, участвующих в графе.
  2. Программа итерируется по отсортированному множеству и генерирует блок объявления компонентов: `component "имя_пакета"`. Это гарантирует, что PlantUML применит движок рендеринга компонентных блок-схем, а не диаграмм последовательности.
  3. Программа обходит граф и формирует связи вида `"пакет" --> "зависимость"`.
  4. Текст обрамляется служебными тегами `@startuml` и `@enduml` и объединяется через символ переноса строки.

## 4. Требования к окружению и запуск

Приложение написано на чистом Python и **не требует установки сторонних библиотек** (зависимости `urllib`, `tarfile`, `gzip` и `re` являются частью стандартной поставки языка).

### Системные требования:
* Python версии 3.8 или выше.
* Стабильное интернет-соединение (для работы с реальным репозиторием Alpine).

### Инструкция по запуску:
1. Клонируйте репозиторий с кодом.
2. Сформируйте конфигурационный файл `config.yaml` в корне проекта.
3. Запустите скрипт через терминал:
   ```bash
   python CLI.py
   ```

## 5. Формат вывода и интеграция с PlantUML

При успешном выполнении утилита выводит в консоль рассчитанный порядок загрузки пакетов, ASCII-дерево (если включено) и текстовый блок диаграммы.

### Пример сгенерированного кода PlantUML:
```text
@startuml
  component "ca-certificates"
  component "curl"
  component "so:libcurl.so.4"
  component "so:libz.so.1"

  "curl" --> "ca-certificates"
  "curl" --> "so:libcurl.so.4"
  "curl" --> "so:libz.so.1"
@enduml
```

### Визуализация графа:
Для получения графической схемы скопируйте вывод программы (включая теги `@startuml` и `@enduml`) и вставьте его на официальном сервере: [PlantUML Online Server](http://plantuml.com). На выходе сформируется корректный направленный граф компонентов с отображением всех уровней вложенности зависимостей.
